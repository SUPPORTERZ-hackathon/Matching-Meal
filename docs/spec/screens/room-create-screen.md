## 現行のAPI接続契約

2026-10-31に承認された[画面03・招待仕様](room-waiting-invite.md)をAPI接続・状態・エラー処理の主仕様とする。既存の画面02の配置・必須入力・12文字上限は維持する。作成APIへ送る項目はnicknameだけで、集合場所と検索範囲はホストのsessionStorage内だけに保持し、未同期である旨を表示する。現在地取得と検索は引き続き未実装。

### 前提・対象外・状態・検証

- 前提：既存Docker Composeのfrontend/backend/dbが稼働し、sessionStorageが利用できること。
- 対象外：バックエンド/API仕様/DB/Docker/環境変数/PWA/共通UIの変更、場所検索・検索条件保存APIの追加。
- 状態：入力→送信中→実セッション保存→待機。送信中は連打を防止し、失敗時は同じ画面にエラーを表示する。保存失敗/不正応答/再送の扱いは主仕様の「参加フォーム・状態・永続化」に従う。
- 受け入れ条件：nicknameだけを既存APIへ送り、成功応答のroom.idで待機へ進むこと。失敗時に架空のQRを表示しないこと。既存の場所/範囲UIを維持し、未同期と分かること。
- 検証方法：主仕様のAPI/ブラウザー/レスポンシブ/コード検証を適用する。検証結果は主仕様のProgressへ集約する。
- 未決定事項：今回の接続範囲にはなし。場所検索・検索条件の同期は別作業。

## 2. 画面の目的

ホストがルームを作成する際に、参加者に表示するニックネームと、お店を検索する中心地点・検索範囲を設定する。

入力内容を確認し、すべての必須項目が入力された場合にルーム作成ボタンを有効にする。

## 3. 画面構成

### 3.1 ヘッダー

- 共通UIの `AppHeader` を使用する。
- `layout="centered"` を指定し、中央配置のレイアウトにする。
- 左側に戻る矢印ボタンを配置する。
- 戻るボタンには共通UIの `Button` を使用する。
- 矢印アイコンには `ArrowLeft` を使用する。
- 戻るボタンを押すと、`router.back()` により前の画面へ戻る。

### 3.2 進行状況表示

- 共通UIの `StepProgress` を使用する。
- `currentStep="room"` を指定する。
- ルーム作成が最初のステップであることを表示する。

### 3.3 タイトル

- ステップ表示：`STEP 1`
- タイトル：`どこで集まる？`
- 説明文：`お店を探す中心地点を決めましょう。`

### 3.4 ニックネーム入力

- カード内にニックネーム入力欄を配置する。
- ラベル：`あなたのニックネーム`
- placeholder：`例：ゆうき`
- 最大入力文字数：12文字
- 文字数カウンターを表示する（例：`5/12`）。
- 補助文：`参加者一覧に表示される名前です`

入力状態に応じてバッジを表示する。

| 状態 | 表示 | 色 |
|---|---|---|
| 未入力 | 未入力 | 赤 |
| 入力済み | 入力OK | 緑 |
| 文字数超過 | 文字数超過 | 赤 |

※ `maxLength={12}` により通常の入力では12文字を超えない。

### 3.5 集合場所入力

- カード内に集合場所の入力欄を配置する。
- ラベル：`集合場所`
- placeholder：`駅名・住所などを入力`
- `MapPin` アイコンを表示する。
- 入力がある場合はクリアボタンを表示する。
- クリアボタンを押すと入力内容を空にする。
- 現在地取得ボタンを配置する。
- 現在地取得機能は現時点ではUIのみで、取得処理は未実装。

### 3.6 検索範囲

- スライダーで検索範囲を5段階から選択する。
- 初期値は1kmとする。
- 選択中の検索範囲を数値で表示する。
- 徒歩時間の目安を表示する。

| 検索範囲 | 徒歩時間の目安 |
|---|---:|
| 300m | 約4分 |
| 500m | 約6分 |
| 1km | 約13分 |
| 2km | 約25分 |
| 3km | 約38分 |

スライダー下部には最小値の300mと最大値の3kmを表示する。

説明文は `徒歩約○分以内のお店を探します` とする。

### 3.7 ルーム作成ボタン

- 共通UIの `BottomAction` 内に配置する。
- 共通UIの `Button` を使用する。
- ボタンの表示文言：`ルームを作成する`
- ニックネームと集合場所の両方が入力されている場合に有効化する。
- いずれかが未入力の場合は無効化する。

## 4. 操作仕様

| 操作 | 動作 |
|---|---|
| 戻るボタン | 前の画面へ戻る |
| ニックネーム入力 | 入力内容と文字数カウンターを更新する |
| 集合場所入力 | 入力内容を更新する |
| クリアボタン | 集合場所の入力内容を消去する |
| 現在地取得ボタン | 現時点ではUIのみ |
| 検索範囲スライダー | 選択した範囲と徒歩時間を更新する |
| ルーム作成ボタン | 既存POST /api/v1/roomsへnicknameを送信し、201の実セッションを保存して待機へ進む |

## 5. 入力チェック

ルーム作成ボタンの有効・無効は以下の条件で判定する。

- ニックネームが空白のみではないこと。
- ニックネームが12文字以内であること。
- 制御文字を含まないこと（既存APIに準拠）。
- 集合場所が空白のみではないこと。

ニックネームは `maxLength={12}` により入力時点で12文字に制限する。

## 6. 画面遷移

### 遷移元
- ホーム画面（`/home-preview`）

### 遷移先
- 作成APIの成功後、`/room-waiting?room={room.id}`。連打防止・処理中・エラー表示を行い、失敗時は架空のルームへ進まない。

### 戻る操作
- ヘッダー左側の戻る矢印を押すと、`router.back()` で前の画面に戻る。

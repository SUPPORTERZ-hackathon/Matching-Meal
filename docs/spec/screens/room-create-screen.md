## 目的と対象範囲

ホストがニックネーム、店舗検索の中心地点、検索範囲を指定し、ルームを作成できるようにする。検索中心は次のいずれか一方で確定する。

1. ブラウザのGeolocation APIで取得した現在地
2. 自由入力で絞り込んだ日本国内の駅候補から選択した駅

駅検索は実行時に外部の駅検索APIやGeocoding APIを呼ばず、国土交通省「国土数値情報（鉄道データ）」を加工してプロジェクトへ同梱した静的データを使用する。

対象URLは`/room-create`とする。作成成功後は実セッションを保存し、`/room-waiting?room={room.id}`へ遷移する。

2026-11-06の取得方式・再送制御・検証結果の主仕様は[frontend-location-and-flow.md](frontend-location-and-flow.md)。高精度15秒から標準20秒への条件付きフォールバック、取得状況・失敗理由・再試行の表示、作成POSTの冪等キーを追加した。許可拒否では再取得しない。住所欄はreadOnlyのままで、住所文字列だけを送信する機能はない。後段の過去の検証記録とは区別する。

### 前提・対象外・状態・検証

## 対象外

- 住所、施設名、郵便番号の検索とGeocoding
- 駅名の読み仮名検索
- GPSまたは駅以外から検索中心を設定する機能
- 実行時の外部駅検索API呼び出し
- 駅データの自動更新
- 廃駅、新駅、駅名変更を公開データの基準日より新しい状態へ独自補正すること
- ルーム作成後の検索地点・検索範囲変更
- バックエンドAPI、DB、Docker、環境変数の変更

## 前提条件

- `POST /api/v1/rooms`は`nickname`、`searchLocation.latitude`、`searchLocation.longitude`、`searchRange`を受け付ける。
- 駅データには、駅名、路線名、運営会社、検索中心として使用できる世界測地系の緯度・経度を含める。
- 駅データの出典、基準年度、加工した事実をREADMEまたは利用者が確認できる文書へ記載する。
- 国土数値情報には公開時点との差や位置誤差があり、現在営業中の全駅と完全に一致することは保証しない。
- sessionStorageが利用できることをルーム作成の前提とする。

## 画面構成

### ヘッダーと進行状況

- 共通`AppHeader`、`PageContainer`、`StepProgress`を使用する。
- `StepProgress`は`currentStep="room"`とする。
- 戻るボタンは`/home-preview`へ遷移する。
- ステップ表示は`STEP 1`、タイトルは`どこで集まる？`、説明文は`お店を探す中心地点を決めましょう。`とする。

### ニックネーム

- ラベルは`あなたのニックネーム`、placeholderは`例：ゆうき`とする。
- 最大12文字とし、文字数カウンターを表示する。
- 未入力、入力済み、文字数超過の状態を既存バッジで表示する。
- 空白だけ、制御文字を含む値、13文字以上は有効な入力として扱わない。

### 集合場所

- ラベルは`集合場所`とする。
- 現在地取得と駅検索の両方を同じカード内へ表示する。
- 現在地と駅は排他的に選択し、同時に確定状態を持たない。
- 確定中の方法と表示名が分かるようにする。緯度・経度の数値は表示しない。

#### 現在地

- `現在地を取得`ボタンでGeolocation APIを呼ぶ。
- 取得中は再実行とルーム作成を無効にする。
- 成功時は検索中心を現在地へ切り替え、選択済みの駅と駅入力を消去する。
- 表示名は`現在地を使用`とする。
- 拒否、未対応、タイムアウト、座標不正、その他失敗は既存の利用者向けエラーを表示し、再試行可能にする。
- 現在地取得の失敗だけでは、すでに選択済みの駅を解除しない。

#### 駅の自由検索

- 編集可能なテキスト入力を表示し、placeholderは`駅名を入力`とする。
- 入力値をtrimし、Unicode NFKCで正規化した駅名に対して部分一致検索する。
- 空文字では候補を表示しない。
- 候補は最大20件とし、完全一致、前方一致、その他の部分一致の順に表示する。同順位は駅名、運営会社、路線名の昇順とする。
- 候補には`駅名`、`路線名`、`運営会社`を表示し、同名駅を区別できるようにする。
- 同名駅が複数の路線・運営会社に存在する場合は、データセット上の別候補として扱う。
- 入力文字列だけでは駅を確定しない。利用者が候補をクリックまたはキーボードで選択した場合だけ駅を確定する。
- 駅を確定したときは、その候補の緯度・経度を検索中心に設定し、取得済み現在地を解除する。
- 選択後に入力値を1文字でも変更した場合は、駅の選択と座標を即時解除する。
- クリア操作は入力、候補、選択済み駅、駅由来の座標を消去する。
- 一致候補がない場合は`一致する駅がありません`と表示する。
- 候補表示中に入力欄外へ移動しても、未選択の入力を確定扱いにしない。

#### キーボードとアクセシビリティ

- 駅入力と候補一覧はcombobox/listboxパターンとし、入力欄から候補の関係と展開状態を支援技術へ通知する。
- `ArrowDown`と`ArrowUp`で候補を移動し、`Enter`で選択し、`Escape`で候補一覧だけを閉じる。
- マウス、タッチ、キーボードのいずれでも同じ候補を選択できる。
- フォーカス中の候補と選択済みの候補を視覚的に区別する。
- エラーと候補なしメッセージは入力欄と関連付ける。

### 検索範囲

- 5段階のスライダーを使用し、初期値は1kmとする。

| 表示 | 徒歩目安 | API `searchRange` |
| --- | ---: | ---: |
| 300m | 約4分 | 1 |
| 500m | 約6分 | 2 |
| 1km | 約13分 | 3 |
| 2km | 約25分 | 4 |
| 3km | 約38分 | 5 |

- 説明文は`徒歩約○分以内のお店を探します`とする。

### ルーム作成ボタン

- 共通`FixedBottomAction`、`BottomAction`、`Button`を使用する。
- 表示文言は`ルームを作成する`とする。
- 有効なニックネームと、現在地または選択済み駅の有効な座標がある場合だけ有効にする。
- 駅名を入力しただけ、候補表示中、駅選択後の文字変更後は無効にする。
- 現在地取得中またはAPI送信中は無効にする。

## 駅データ要件

### データソース

- 国土交通省「国土数値情報（鉄道データ）」の、実装時点で取得可能な最新公開版を使用する。
- 全国の旅客鉄道・軌道の駅を対象とし、貨物線、構内専用線、引込線、索道など原典の対象外データは追加しない。
- 取得元URL、取得日、基準年度、原典ライセンス、加工方法をデータ更新手順へ記録する。
- 生成済みデータへ出典と加工の事実を付記し、原典の利用条件に従う。

### 加工と形式

- 原典から駅名、路線名、運営会社、駅形状を抽出する。
- 同じ駅コードの駅形状を統合し、全線分の長さに沿った中間点を検索中心として決定的に算出する。WGS84の有限な緯度・経度として保存する。
- 実行時にGISファイル全体を読み込まず、検索に必要な項目だけを持つ生成済み静的データを使用する。
- 各レコードには安定した内部ID、駅名、路線名、運営会社、緯度、経度を含める。
- TypeScriptと変換処理で緯度-90〜90、経度-180〜180、必須文字列の非空を検証し、不正レコードを配布データへ含めない。
- 原典と生成済みデータは手編集せず、再現可能な変換スクリプトで更新する。

### 配信と性能

- 駅データはアプリと同一オリジンの静的アセットとして配信し、外部サービスへ検索語や座標を送信しない。
- 駅データ取得中はローディング状態を表示する。取得失敗時は現在地取得を引き続き利用可能とし、駅検索だけに再試行導線を表示する。
- 文字入力のたびに全候補DOMを生成せず、最大20件だけを表示する。
- データサイズと検索応答時間を実装時に計測し、Progressへ記録する。

## 状態と状態遷移

| 状態 | 確定座標 | ルーム作成 |
| --- | --- | --- |
| 集合場所未選択 | なし | 不可 |
| 現在地取得中 | なし、または既存の駅選択を維持 | 不可 |
| 現在地取得済み | 現在地 | 可 |
| 現在地取得失敗 | 失敗前に駅選択があれば駅、なければなし | 駅選択の有無による |
| 駅入力中・未選択 | なし | 不可 |
| 駅候補選択済み | 選択駅 | 可 |
| 選択済み駅の文字変更後 | なし | 不可 |
| 駅データ取得失敗 | なし | 不可。ただし現在地を選択可能 |
| ルーム作成中 | 選択中の座標を固定 | 不可 |

- 駅選択済みの状態から現在地取得を開始した時点では駅選択を保持し、成功した場合だけ現在地へ切り替える。
- 現在地選択済みの状態で駅名を入力し始めた時点で現在地を解除し、候補選択まで集合場所未選択とする。
- 送信中はニックネーム、集合場所、検索範囲の変更と再送を防止する。

## 入出力と保存

- 送信値は既存API契約どおり、`nickname`、確定した`searchLocation.latitude`、`searchLocation.longitude`、`searchRange`とする。
- 駅名、路線名、運営会社、選択方法はバックエンドへ送らない。
- 作成成功時、sessionStorageの表示用`localSearch.location`には`現在地を使用`または選択した駅名を保存し、`radiusMeters`へ範囲を保存する。
- 緯度・経度はReact状態だけに保持し、sessionStorage、URL、画面、通常ログへ保存・表示しない。
- API成功時は実セッションを保存して待機画面へ進む。保存不能またはAPI失敗時は同じ画面で再試行可能なエラーを表示する。

## エラー処理と境界条件

- 駅データが読み込めなくても現在地取得を妨げない。
- 同じ表示名の候補があっても、自動的に先頭候補を確定しない。
- 入力と完全一致する駅が1件だけでも、候補選択なしでは確定しない。
- IME変換中は`Enter`を候補選択として扱わない。
- 選択操作時点で候補が現在の検索結果に含まれない場合は確定しない。
- 無効な駅座標を受け取った場合は選択を拒否し、駅データエラーとして扱う。
- 現在地と駅のどちらを選んでも、APIへ送る直前に座標の有限性と範囲を再検証する。
- API送信中は二重送信を防止し、失敗後は同じ確定済み集合場所で再送できる。

## レスポンシブ動作

- 既存のスマートフォン優先レイアウト、セーフエリア、下部固定ボタンを維持する。
- 候補一覧は入力欄の幅に合わせ、画面外へ横にはみ出さない。
- 候補の駅名、路線名、運営会社が長い場合は複数行または省略表示とし、選択領域はタッチ操作可能な高さを確保する。
- デスクトップでも候補一覧と下部アクションが重ならない。

## 受け入れ条件

1. 現在地取得または駅候補選択のどちらかで検索中心を確定できる。
2. 駅名を入力しただけではルームを作成できない。
3. 候補から駅を選ぶと、その駅の座標でルームを作成できる。
4. 選択後に入力文字を変更すると駅選択が解除され、再選択まで作成できない。
5. 現在地の取得成功と駅選択は排他的で、最後に成功・選択した方法だけが使用される。
6. 現在地取得失敗時に既存の駅選択が失われず、駅データ取得失敗時にも現在地を利用できる。
7. 同名駅を路線名と運営会社で区別でき、先頭候補が自動確定されない。
8. キーボード、タッチ、マウスで候補を選択でき、IME変換確定を駅選択と誤認しない。
9. 実行時に外部の駅検索・Geocoding APIを呼ばない。
10. 駅データの出典、基準年度、取得日、加工方法、利用上の時間差を確認できる。
11. 現在地・駅のどちらでも既存APIへ有効な緯度、経度、検索範囲1〜5を送る。
12. 緯度・経度を画面、URL、sessionStorage、通常ログへ残さない。
13. 送信中の二重送信を防ぎ、成功時だけ実セッションを保存して待機画面へ進む。

## 検証方法

- 駅データ変換を同じ入力から複数回実行し、同一出力になることを確認する。
- 必須項目、重複ID、座標範囲、件数、全国データの存在を自動検証する。
- 完全一致、前方一致、部分一致、0件、20件超、同名駅、全角・半角、前後空白を単体テストする。
- 候補未選択、候補選択、選択後編集、クリア、現在地との相互切替をコンポーネントテストする。
- Arrowキー、Enter、Escape、IME変換、タッチ選択とARIA属性を確認する。
- 駅データの読込中・失敗・再試行と、その状態での現在地取得を確認する。
- Geolocation APIの成功、拒否、未対応、タイムアウト、座標不正を確認する。
- 5段階の検索範囲とAPI値1〜5の対応を確認する。
- 作成リクエスト、二重送信防止、失敗後の再試行、sessionStorageの保存内容を確認する。
- 360px以下のスマートフォン幅、一般的なスマートフォン幅、デスクトップ幅で候補一覧と固定ボタンを目視確認する。
- Docker Compose内でfrontendのlint、typecheck、テスト、buildを実行する。

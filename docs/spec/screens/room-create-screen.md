# ルーム作成画面 仕様書

## 1. 画面概要

| 項目 | 内容 |
|---|---|
| 画面名 | ルーム作成画面 |
| 画面ID | room-create |
| URL | `/room-create` |
| 目的 | ルーム作成に必要なニックネーム・集合場所・検索範囲を設定する |

## 2. 画面の目的

ホストがルームを作成する際に、参加者に表示するニックネームと、お店を検索する中心地点・検索範囲を設定する。

入力内容を確認し、すべての必須項目が入力された場合にルーム作成ボタンを有効にする。

## 3. 画面構成

### 3.1 ヘッダー

- 共通UIの `AppHeader` を使用する。
- `layout="centered"` を指定し、中央配置のレイアウトにする。
- 左側に戻る矢印ボタンを配置する。
- 戻るボタンには共通UIの `Button` を使用する。
- 矢印アイコンには `ArrowLeft` を使用する。
- 戻るボタンを押すと、`router.back()` により前の画面へ戻る。

### 3.2 進行状況表示

- 共通UIの `StepProgress` を使用する。
- `currentStep="room"` を指定する。
- ルーム作成が最初のステップであることを表示する。

### 3.3 タイトル

- ステップ表示：`STEP 1`
- タイトル：`どこで集まる？`
- 説明文：`お店を探す中心地点を決めましょう。`

### 3.4 ニックネーム入力

- カード内にニックネーム入力欄を配置する。
- ラベル：`あなたのニックネーム`
- placeholder：`例：ゆうき`
- 最大入力文字数：12文字
- 文字数カウンターを表示する（例：`5/12`）。
- 補助文：`参加者一覧に表示される名前です`

入力状態に応じてバッジを表示する。

| 状態 | 表示 | 色 |
|---|---|---|
| 未入力 | 未入力 | 赤 |
| 入力済み | 入力OK | 緑 |
| 文字数超過 | 文字数超過 | 赤 |

※ `maxLength={12}` により通常の入力では12文字を超えない。

### 3.5 集合場所入力

- カード内に集合場所の入力欄を配置する。
- ラベル：`集合場所`
- placeholder：`駅名・住所などを入力`
- `MapPin` アイコンを表示する。
- 入力がある場合はクリアボタンを表示する。
- クリアボタンを押すと入力内容を空にする。
- 現在地取得ボタンを配置する。
- 現在地取得機能は現時点ではUIのみで、取得処理は未実装。

### 3.6 検索範囲

- スライダーで検索範囲を5段階から選択する。
- 初期値は1kmとする。
- 選択中の検索範囲を数値で表示する。
- 徒歩時間の目安を表示する。

| 検索範囲 | 徒歩時間の目安 |
|---|---:|
| 300m | 約4分 |
| 500m | 約6分 |
| 1km | 約13分 |
| 2km | 約25分 |
| 3km | 約38分 |

スライダー下部には最小値の300mと最大値の3kmを表示する。

説明文は `徒歩約○分以内のお店を探します` とする。

### 3.7 ルーム作成ボタン

- 共通UIの `BottomAction` 内に配置する。
- 共通UIの `Button` を使用する。
- ボタンの表示文言：`ルームを作成する`
- ニックネームと集合場所の両方が入力されている場合に有効化する。
- いずれかが未入力の場合は無効化する。

## 4. 操作仕様

| 操作 | 動作 |
|---|---|
| 戻るボタン | 前の画面へ戻る |
| ニックネーム入力 | 入力内容と文字数カウンターを更新する |
| 集合場所入力 | 入力内容を更新する |
| クリアボタン | 集合場所の入力内容を消去する |
| 現在地取得ボタン | 現時点ではUIのみ |
| 検索範囲スライダー | 選択した範囲と徒歩時間を更新する |
| ルーム作成ボタン | 現時点では作成処理未実装 |

## 5. 入力チェック

ルーム作成ボタンの有効・無効は以下の条件で判定する。

- ニックネームが空白のみではないこと。
- ニックネームが12文字以内であること。
- 集合場所が空白のみではないこと。

ニックネームは `maxLength={12}` により入力時点で12文字に制限する。

## 6. 画面遷移

### 遷移元
- ホーム画面（`/home-preview`）

### 遷移先
- 現時点ではルーム作成処理・待機画面への遷移は未実装。

### 戻る操作
- ヘッダー左側の戻る矢印を押すと、`router.back()` で前の画面に戻る。

## 7. デザイン・実装方針

- スマートフォンでの利用を前提としたレイアウトにする。
- 共通UIの `AppHeader`、`PageContainer`、`BottomAction`、`Button`、`StepProgress` を再利用する。
- 入力欄はカード形式でまとめる。
- カードには共通CSSの `.meal-card` を使用する。
- カード間の余白は16pxとする。
- 画面下部にルーム作成ボタンを配置する。
- スマートフォンのセーフエリアを考慮する。
- 色や余白、ボタンのデザインはアプリ全体で統一する。

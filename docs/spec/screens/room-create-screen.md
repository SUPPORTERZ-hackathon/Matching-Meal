## 1. 画面概要

| 項目 | 内容 |
|---|---|
| 画面名 | ルーム作成画面 |
| 画面ID | room-create |
| URL | `/room-create` |
| 目的 | ルーム作成に必要なニックネーム・集合場所・検索範囲を設定する |

## 2. 画面の目的

ホストがルームを作成する際に、参加者に表示するニックネームと、お店を検索する中心地点・検索範囲を設定する。

入力内容を確認し、すべての必須項目が入力された場合にルーム作成ボタンを有効にする。

## 3. 画面構成

### 3.1 ヘッダー

- 共通UIの `AppHeader` を使用する。
- `layout="centered"` を指定し、中央配置のレイアウトにする。
- 左側に戻る矢印ボタンを配置する。
- 戻るボタンには共通UIの `Button` を使用する。
- 矢印アイコンには `ArrowLeft` を使用する。
- 戻るボタンを押すと、`router.back()` により前の画面へ戻る。

### 3.2 進行状況表示

- 共通UIの `StepProgress` を使用する。
- `currentStep="room"` を指定する。
- ルーム作成が最初のステップであることを表示する。

### 3.3 タイトル

- ステップ表示：`STEP 1`
- タイトル：`どこで集まる？`
- 説明文：`お店を探す中心地点を決めましょう。`

### 3.4 ニックネーム入力

- カード内にニックネーム入力欄を配置する。
- ラベル：`あなたのニックネーム`
- placeholder：`例：ゆうき`
- 最大入力文字数：12文字
- 文字数カウンターを表示する（例：`5/12`）。
- 補助文：`参加者一覧に表示される名前です`

入力状態に応じてバッジを表示する。

| 状態 | 表示 | 色 |
|---|---|---|
| 未入力 | 未入力 | 赤 |
| 入力済み | 入力OK | 緑 |
| 文字数超過 | 文字数超過 | 赤 |

※ `maxLength={12}` により通常の入力では12文字を超えない。

### 3.5 集合場所入力

- カード内に集合場所の入力欄を配置する。
- ラベル：`集合場所`
- placeholder：`駅名・住所などを入力`
- `MapPin` アイコンを表示する。
- 入力がある場合はクリアボタンを表示する。
- クリアボタンを押すと入力内容を空にする。
- 現在地取得ボタンを配置する。
- 現在地取得ボタンでブラウザのGeolocation APIから世界測地系の緯度・経度を取得する。
- 取得成功後は集合場所欄に「現在地を使用」と表示し、緯度・経度の数値自体は画面に表示しない。
- 取得拒否、未対応、タイムアウト、その他の取得失敗ではルームを作成せず、再試行可能なエラーを表示する。
- 駅名・住所の入力とGeocodingは今回の対象外とし、集合場所の自由入力欄は無効化または非表示にする。

### 3.6 検索範囲

- スライダーで検索範囲を5段階から選択する。
- 初期値は1kmとする。
- 選択中の検索範囲を数値で表示する。
- 徒歩時間の目安を表示する。

| 検索範囲 | 徒歩時間の目安 |
|---|---:|
| 300m | 約4分 |
| 500m | 約6分 |
| 1km | 約13分 |
| 2km | 約25分 |
| 3km | 約38分 |

スライダー下部には最小値の300mと最大値の3kmを表示する。

説明文は `徒歩約○分以内のお店を探します` とする。

### 3.7 ルーム作成ボタン

- 共通UIの `BottomAction` 内に配置する。
- 共通UIの `Button` を使用する。
- ボタンの表示文言：`ルームを作成する`
- ニックネームが有効で、現在地取得が成功している場合に有効化する。
- 現在地の取得中、未取得、取得失敗、またはニックネーム不正の場合は無効化する。

## 4. 操作仕様

| 操作 | 動作 |
|---|---|
| 戻るボタン | 前の画面へ戻る |
| ニックネーム入力 | 入力内容と文字数カウンターを更新する |
| 集合場所入力 | 今回は駅名・住所入力を受け付けない |
| クリアボタン | 取得済み現在地を破棄し、未取得状態へ戻す |
| 現在地取得ボタン | 取得中表示にして現在地を取得し、成功時に「現在地を使用」と表示する |
| 検索範囲スライダー | 選択した範囲と徒歩時間を更新する |
| ルーム作成ボタン | ニックネーム、取得済み緯度・経度、検索範囲をルーム作成APIへ送る |

## 5. 入力チェック

ルーム作成ボタンの有効・無効は以下の条件で判定する。

- ニックネームが空白のみではないこと。
- ニックネームが12文字以内であること。
- 現在地の取得が成功し、有効な緯度・経度を保持していること。

ニックネームは `maxLength={12}` により入力時点で12文字に制限する。

## 11. 状態とエラー

現在地は`未取得`、`取得中`、`取得済み`、`取得失敗`の4状態とする。取得開始時は取得中、成功時は取得済み、拒否・未対応・タイムアウト・その他失敗時は取得失敗へ遷移する。取得失敗後も現在地取得ボタンで再試行できる。

ルーム作成APIの送信中は二重送信を防止する。入力不正は入力箇所付近、API失敗はルーム作成ボタン付近へ利用者向けメッセージを表示し、現在地とAPIキーをエラー本文へ表示しない。

## 12. 受け入れ条件

1. 現在地取得成功後だけ、有効なニックネームと組み合わせてルーム作成できる。
2. 取得拒否、未対応、タイムアウト、取得失敗時はルーム作成せず再試行できる。
3. APIへ緯度、経度、選択中の検索範囲1〜5を送る。
4. 緯度・経度の数値を画面、通常ログ、URLへ出さない。
5. 送信中の二重送信を防ぎ、失敗後は再送できる。
6. 駅名・住所の入力を検索条件として送らない。

## 13. 検証方法

- Geolocation APIをモックし、成功、拒否、未対応、タイムアウト、その他失敗を確認する。
- 5段階それぞれの検索範囲がAPI値1〜5へ対応することを確認する。
- ルーム作成リクエスト、二重送信防止、API失敗後の再試行を確認する。
- 位置情報の数値が画面、URL、テストログへ出ないことを確認する。
- Docker Compose内でfrontend lint、typecheck、テスト、buildを実行する。

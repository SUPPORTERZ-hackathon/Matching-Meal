# ホーム画面仕様書

- Status: UIデザイン確定
- 対象ルート: `/home-preview`
- 対象画面: メシマッチのホーム画面
- 関連仕様: `docs/spec/components/common-ui.md`、`docs/spec/themes/design-system.md`

## 1. 目的

メシマッチの利用開始画面を作成する。ユーザーがルーム作成または既存ルームへの参加を選択できる、スマートフォン向けのホーム画面を提供する。

本仕様書では、最終確認した画面デザインを基準として、画面構成、見た目、レイアウト、レスポンシブ対応および確認項目を定義する。

## 2. 実装範囲

- `/home-preview` にホーム画面のプレビューを実装する。
- 既存の `/` にあるAPI・DB接続確認ページは変更しない。
- 既存の `AppLogo`、`PageContainer`、`Button` を再利用する。
- 料理写真を配置するためのコラージュ領域を作成し、写真は後から差し替えられる構成にする。
- 画面の見た目とレイアウトを対象とし、ルーム作成、QRコード読み取り、実際の画面遷移は別途実装する。
- 最終デザインのスクリーンショットを基準とし、今後の修正では確定済みの配置や余白を不用意に変更しない。

## 3. 画面構成

画面上部から順に、以下の要素を配置する。

### 3.1 アプリロゴ

- 既存の `AppLogo` を使用する。
- 「M」のマークと「メシマッチ」の文字を左寄せで配置する。
- 画面上部に適切な余白を設ける。
- スマートフォンのセーフエリアを考慮し、ノッチやステータスバーと重ならないようにする。
- ホーム画面専用のロゴを新規作成せず、既存コンポーネントを再利用する。

### 3.2 料理画像エリア

- 中央に大きな料理カードを配置し、左右に小さな料理カードを配置する。
- 中央のカードを主役とし、左右のカードは一部が画面端からはみ出す構成にする。
- 各カードには白い縁取り、角丸、控えめな影を設定する。
- 中央のカードには右下付近にハートマークを配置する。
- 写真同士の重なり方や位置関係を維持しながら、画面幅に応じてカードサイズを調整する。
- 現段階では写真を後から差し替えられるよう、画像領域と配置の構造を用意する。
- 写真を差し替える際は、画像の比率や表示方法を調整し、カードの形状やレイアウトが崩れないようにする。
- 画像の読み込みに失敗した場合も、カードの背景色やサイズを維持する。

### 3.3 キャッチコピー

補助コピー：

「もう『どこ行く？』で迷わない」

メインコピー：

「みんなで決める、」
「ご飯選び！」

説明文：

「好きな料理を選ぶだけ。みんなの『食べたい』が重なるお店を見つけよう。」

- コピーと説明文は中央揃えにする。
- メインコピーは2行で表示する。
- 1行目は通常の文字色、2行目はブランドカラーの赤で強調する。
- 補助コピーはメインコピーより小さくし、控えめな色と太さで表示する。
- 説明文は読みやすい文字サイズと行間を設定する。
- 料理画像エリアとキャッチコピーの間隔を確保し、各要素が密集しすぎないようにする。
- フォントは共通デザインシステムの指定を優先する。

### 3.4 メインボタン

- 表示文言：「ルームを作成する」
- 既存の `Button` を使用する。
- 基本設定は `variant="primary"`、`size="meal"` とする。
- ブランドカラーの赤を背景色とする。
- ボタン内の文字は中央に配置する。
- 右端に `ChevronRight` アイコンを配置する。
- プラスアイコンは表示しない。
- サブボタンと統一感のある高さ、角丸、文字サイズを使用する。
- 画面下部に配置し、十分なタップ領域を確保する。

### 3.5 サブボタン

- 表示文言：「QRコードから参加する」
- 既存の `Button` を使用する。
- 基本設定は `variant="outline"`、`size="meal"` とする。
- 白を基調とした背景とし、枠線や影は控えめにする。
- QRコードアイコンを表示する。
- アイコンと文字を見やすく配置する。
- メインボタンの下に配置し、ボタン間の余白を確保する。
- メインボタンと高さ、角丸、文字サイズの統一感を保つ。

### 3.6 フッター

- サブボタンの下に補助テキストを配置する。
- 表示文言：「登録不要・すぐにはじめられます」
- 文字色は共通デザインシステムの `muted-foreground` を基本とする。
- 文字サイズは小さめに設定し、メインコンテンツの邪魔にならないようにする。
- サブボタンと補助テキストの距離を適切に保つ。
- 画面下部のセーフエリアを考慮し、端末の操作領域と重ならないようにする。

## 4. デザイン要件

- 共通デザインシステムのカラー、フォント、余白、角丸を優先する。
- 背景は温かみのある明るい色を基本とする。
- メインカラーにはブランドカラーの赤を使用する。
- メインボタンは赤、サブボタンは白を基本とする。
- 料理画像エリアを視覚的な主役とし、操作ボタンも見つけやすくする。
- ロゴ、料理画像、コピー、ボタン、フッターの間隔を調整し、画面全体のバランスを保つ。
- iPhone 16で確認した最終レイアウトを基準とする。
- ほかの画面サイズでは、要素の大きさや余白を調整してバランスを維持する。
- 横スクロールや文字の重なりを発生させない。
- 画面専用のCSSを使用する場合も、既存のクラス名や共通コンポーネントを尊重し、必要な部分のみを変更する。

## 5. レイアウト・レスポンシブ要件

### 5.1 基本方針

- スマートフォンでの利用を主な対象とする。
- 画面幅に応じて、料理カードの幅や高さ、左右のはみ出し量を調整する。
- 画面の高さに応じて、上部・中央・下部の余白を調整する。
- ロゴ、画像、コピー、ボタン、フッターの位置関係を可能な限り維持する。
- 固定値だけに依存せず、必要に応じて `clamp()`、メディアクエリ、フレックスレイアウトなどを利用する。
- 負のマージンなどで位置を無理に調整する場合は、ほかの画面サイズで崩れないか確認する。
- 画面の高さが小さい端末でも、ボタンや説明文が画面外にはみ出さないようにする。
- セーフエリアを考慮し、上下端にコンテンツが密着しすぎないようにする。

### 5.2 確認対象の画面幅

- ihone SE
- ihone16
- ihone16ProMax
- Pixel9
- Pixel9Pro
- Pixel10

## 6. 共通コンポーネントの利用

- `PageContainer` を画面の外枠として使用する。
- ホーム画面独自のロゴ配置とするため、必要に応じて `header={null}` を指定する。
- `AppLogo` は既存実装を使用する。
- ボタンは既存の `Button` を使用し、独自のボタンコンポーネントを作成しない。
- `variant` と `size` による共通スタイルを優先する。
- 共通デザイントークンを優先し、画面専用のグローバルCSS変更は行わない。
- ホーム画面のCSSは、既存のクラス名を維持しながら必要なスタイルだけを調整する。

## 7. 動作要件

- ルーム作成ボタンとQRコードから参加するボタンを表示する。
- 現段階では、実際のルーム作成、QRコード読み取り、画面遷移の処理は対象外とする。
- 実装されていない機能が動作するように見せかけない。
- 後続の実装で実際の機能を接続できる構成にする。
- 料理画像を差し替えた際も、画面全体のレイアウトが崩れないようにする。

## 8. アクセシビリティ

- ボタンの表示文言から操作内容を理解できるようにする。
- アイコンだけで操作内容を伝えない。
- 装飾目的の画像には適切な代替テキスト方針を設定する。
- 意味のある料理画像には内容を説明する代替テキストを設定する。
- キーボードフォーカスを視認できるようにする。
- 動きを追加する場合は、動きを減らす設定にも配慮する。
- 文字色と背景色のコントラストを確認する。

## 9. 確認項目

### 9.1 表示確認

- `/home-preview` でホーム画面が表示される。
- `/` のAPI・DB接続確認ページが変更されていない。
- ロゴ、料理画像エリア、キャッチコピー、説明文、2つのボタン、フッターが表示される。
- 中央の料理カードが左右のカードより大きく表示される。
- 左右のカードが画面端から一部はみ出すレイアウトになっている。
- 中央のカードにハートマークが表示される。
- メインボタンには「ルームを作成する」と右向き矢印が表示され、プラスアイコンは表示されない。
- サブボタンにはQRコードアイコンと「QRコードから参加する」が表示される。
- フッターの補助テキストがサブボタンから離れすぎていない。

### 9.2 レスポンシブ確認

- 指定した画面幅でレイアウトを確認する。
- 横スクロールが発生しない。
- 文字やボタンが重ならない。
- 画面の高さが異なる場合も、主要な要素が見切れない。
- セーフエリアと端末の操作領域を考慮した配置になっている。
- iPhone 16で確認したデザインのバランスが維持されている。

### 9.3 品質確認

- 既存の共通コンポーネントとデザイントークンを再利用している。
- 料理画像を差し替えても、カードの形状と配置が維持される。
- 画像読み込み失敗時にもレイアウトが崩れない。
- ボタンのフォーカス表示を確認する。
- ビルドと既存テストを実行し、結果を記録する。

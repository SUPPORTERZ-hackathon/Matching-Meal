# ルーム参加画面 仕様書

## 1. 画面概要

| 項目 | 内容 |
|---|---|
| 画面名 | ルーム参加画面 |
| 画面ID | room-join |
| URL | `/room-join` |
| 目的 | QRコードから参加するルームの情報を確認し、ニックネームを入力して参加する |
| 対象ユーザー | ルームに参加するメンバー |

本画面は、QRコードの読み込み後に表示する画面である。

参加者は表示されたルーム情報を確認し、ニックネームを入力して「参加する」ボタンを押すことで、ルームへの参加を進める。

## 2. 画面構成

画面は主に以下の要素で構成する。

### 2.1 ヘッダー

- メシマッチのロゴを表示する。
- 右側にルーム番号を表示する。
- ルーム番号は `Room #2481` のような形式で表示する。

### 2.2 招待・ルーム情報

参加するルームの情報を表示する領域。

表示内容：
- 人型アイコン
- 「招待されています」という案内文
- ルーム名
- 集合場所・検索地点の情報

表示例：
- ルーム名：ゆうきさんのルーム
- 場所：渋谷駅から1.5km

※ 現在は仮のルーム情報を使用している。

### 2.3 ニックネーム入力欄

ルーム内で使用するニックネームを入力する。

| 項目 | 内容 |
|---|---|
| ラベル | ニックネーム |
| プレースホルダー | 例：みさき |
| 最大文字数 | 12文字 |
| 補足文 | ルーム内で表示される名前です |

入力欄の下部には、現在の入力文字数を `0/12` の形式で表示する。

入力状態に応じて、ラベル横の表示を切り替える。

| 入力状態 | 表示 |
|---|---|
| 未入力 | 未入力 |
| 1〜12文字 | 入力OK |
| 12文字超過 | 文字数超過 |

「入力OK」の場合は緑色で表示し、それ以外は赤色で表示する。

### 2.4 参加ボタン

画面下部に「参加する」ボタンを配置する。

- ニックネームが入力されていない場合は無効化する。
- ニックネームが12文字以内で入力されている場合は有効化する。
- 無効状態ではボタンを押せないようにする。
- ボタンの右側に矢印アイコンを表示する。

※ ボタンの画面内での配置や余白は、今後ほかの画面と合わせて全体的に統一・調整する予定。

## 3. 操作仕様

| 操作 | 動作 |
|---|---|
| ニックネーム入力 | ニックネームを入力する |
| 入力内容の変更 | 入力内容に応じて文字数と入力状態を更新する |
| 参加するボタン | 入力条件を満たした場合に有効になる |
| 参加するボタン押下 | ルーム参加処理へ進む（今後実装） |

## 4. 入力チェック仕様

ニックネームは以下の条件で判定する。

- 空文字・空白のみの場合は参加不可。
- 12文字以内の場合は参加可能。
- 12文字を超える場合は参加不可。
- 入力文字数をリアルタイムで表示する。

参加ボタンの有効条件：

```tsx
const canJoin =
  nickname.trim().length > 0 && nickname.length <= 12;
```

入力欄には `maxLength={12}` を設定し、通常の入力操作では12文字を超えないようにする。

## 5. 画面遷移

想定する画面遷移は以下のとおり。

1. ホーム画面で「QRコードから参加する」を選択する。
2. QRコード読み取り画面へ移動する。
3. QRコードを読み取る。
4. 読み取ったルーム情報をもとにルーム参加画面を表示する。
5. 参加者がニックネームを入力する。
6. 「参加する」ボタンを押す。
7. 参加処理完了後、参加者待機画面へ移動する。

※ 現在は画面遷移と参加処理の一部が未実装であり、今後実装する。

## 6. デザイン・レイアウト方針

- スマートフォンでの利用を前提とする。
- 赤色をメインカラーとし、白や薄いグレーを組み合わせる。
- 招待されていることが直感的に分かるように、人型アイコンと案内文を中央に配置する。
- ルーム名と場所を見やすく表示する。
- ニックネーム入力欄はカード形式でまとめる。
- 参加ボタンは押しやすさを意識する。
- ヘッダーやフッターの余白・配置については、他画面との統一を考慮して今後調整する。
